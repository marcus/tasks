## What this review attacked

The prior seven reviews between them swept single code points exhaustively
(per sigil, for `String#inspect`, for `String#downcase`) and swept `Float#to_s`
over 200k literals. This review deliberately attacked the shapes those sweeps
*cannot express*, because that is where the last four defects hid:

1. **Symbol names of two or more code points** that compose a sigil, a
   trailing `?`/`!`/`=`, and printable-versus-non-printable non-ASCII —
   `@a=`, `$a?`, `a?=`, `é?`, `@@éZ`, `$-éé`, `a<NEL>`, `a<ZWSP>b`,
   `a<U+2028>b`, `<emoji>a`, and the whole operator table plus its near
   misses (`..`, `&&`, `::`, `&.`, `<<=`, `=>`, `!@`, `~@`).
2. **Nested and extreme values through `Array(values).map(&:to_s)`** —
   containers three deep, duplicate Hash keys, `-0`, `1e400`, `5e-324`, the
   `point == 15/16/17` float-layout boundaries, and integers wider than

3. **`parse_cli` argument shapes** around the regex boundaries — `""`, `-`,
   `--`, `-Ax`, `+`, `+\n`, `+a\nb`, `+\nab`, `/`, `//x`, repeated and
   conflicting scope aliases, and every mutual-exclusion pairing.
4. **Constructor keyword coercion order** — unknown keyword versus domain
   error precedence, duplicate keys, all thirteen keywords at once.

## The b13485b repair, independently reproduced

Both rules the repair introduced were re-derived from Ruby's
`is_special_global_name` and then confirmed by sweep, not taken from the
handoff:

- **`$-X`** is bare iff exactly one character follows the dash and it is an
  identifier character, with non-ASCII admitted subject to the same
  printability predicate a solo bare symbol uses. `dashGlobalName`
  (`coerce.go:214`) is exactly that; `$-`, `$-ab`, `$--` and `$-͸` all quote in
  both runtimes.
- **`$0`** is a member of Ruby's punct set, so the name must end after it,
  which is what leaves the digit branch reachable only through `1`-`9`.
  `globalName` (`coerce.go:190`) orders `identifier` → dash → nonzero-leading
  digits → `specialGlobals`; every ordering interaction I could construct
  (`$0abc`, `$1a`, `$00`, `$0123`, `$19`, `$_x`, `$;`, `$%`) agrees with Ruby.

## Re-derived and confirmed, not merely re-run

- `filter.go:18` `stateOrder` and the three scoped vocabularies at
  `filter.go:227-248` are byte-identical to `Store::STATES`, `OPEN_STATES`,
  `PROPOSED_STATES` and `CLOSED_STATES` as the running Ruby reports them.
- `bareSymbolName`'s operator list (`coerce.go:166`) matches Ruby's
  `rb_enc_symname_type` switch exactly, including the four traps: `..`,
  `...`, `&&`, `||`, `::` and `&.` are in Ruby's `op_tbl` but are *not* bare
  symbols, and `!@`/`~@` are correctly absent while `+@`/`-@` are present.
- The trailing-suffix rule at `coerce.go:179` — `TrimRight` then a strict
  "exactly one character removed" test — reproduces Ruby's `id:` label,
  including that a suffix is refused for the `$`, `@` and `@@` types
  (`:@a=`, `:$a?` quote) and that `a?=`, `a!=`, `a==` all quote.
- `quoteRuby`'s case order (`coerce.go:442`) is safe against Ruby's different
  order — Ruby tests printability *before* the named escapes, Go after — only
  because no named-escape character is printable to Ruby. That is true, and
  the exhaustive escape differential confirms it.
- `ParseCLI`'s invalid-UTF-8 guard (`filter.go:115`) sits before the literal
  comparisons rather than at the first regex `when`. The argument order is
  still observable-identical because every Ruby `when` literal is ASCII, so an
  argument with invalid bytes can never equal one.

## Recorded, not filed as findings

- `identifier` (`coerce.go:238`) tests `index > 0` on the **byte** index of a
  `range` loop, not a rune index. It is correct — byte index 0 is the first
  rune and no other rune has index 0 — but it reads as a latent bug. A comment
  or a rune counter is a Go-idiom question, not a fidelity one.
- `strings.ToUpper` at `filter.go:77` and `:84` remains the upcase mirror of
  the `newerUnicodeLower` coupling. I re-checked the bound rather than
  inheriting it: for Go to diverge observably, some input's Ruby `upcase`
  image would have to be exactly `A`, `B`, `C`, or a state name while Go's
  simple mapping produces something else. Ruby's multi-character expansions
  (`ß`→`SS`, `ﬁ`→`FI`, `ﬅ`→`ST`, `ŉ`→`ʼN`) and the Unicode 16/17 additions
  produce no such image. The bound holds; it is still a coupling any later
  case-changing slice inherits.
- Non-object kwargs remain inexpressible as a conformance case: the Ruby probe
  dies in its own `transform_keys` before `TaskFilter.new` is reached. This is
  a probe limit, not missing coverage of the subject.
