## Finding 1 — Hash key order

`query.Object` is a Ruby Hash as ordered `Entry{Key, Value}` pairs, and
`query.DecodeValue` is now the package's single boundary decoder: a token-stream
decode that keeps document order, keeps numbers as `json.Number`, and gives a
repeated key its first position with its last value, as `Hash#[]=` does. The
`map[string]any` case is gone from `rubyArray` and `rubyInspect` — a Ruby Hash
has an order, so the Go shape that represents one has to carry it, and leaving
a sorted-map path in place would have left the defect reachable.

The probe drops `keywordOrder` and `decodeGeneric` entirely: the ordered decode
they were each half of is now one function, and `rejectUnknownKeywords` reads
the order straight off the `Object`.

## Finding 2 — Float elements

`rubyNumber` splits Integer from Float the way Ruby's JSON parser does, on the
literal's shape: a `.`, `e`, or `E` makes it a Float. Integers go through
`math/big`, which preserves arbitrary width and renormalises `-0` to `0` — the
one JSON literal that needs it, and a fourth divergence the review did not
name. Floats go through `rubyFloatToS`, Ruby's `Float#to_s`:

- shortest round-trip digits, from `strconv.FormatFloat(_, 'e', -1, 64)`;
- with the decimal point at `point` (dtoa's `decpt`): fixed while
  `point <= 15`; fixed at `point == 16` **only while a fractional digit
  remains**, which is why `1e15` prints `1.0e+15` but `1000000000000000.5`
  prints in full; `0.000ddd` for `-4 < point <= 0`; exponent form otherwise;
- a fixed rendering always carries a fractional digit, so `100.0` never
  prints as `100`;
- the exponent is signed with at least two digits (`1.0e-05`, `5.0e-324`).

The `point == 16` rule is not in the review's correction, which proposed
`exp >= 16` alone; that would have printed `1234567890123456.8` as
`1.2345678901234568e+15`. It was derived from Ruby and then proved, not guessed.

## Finding 3 — `String#inspect`

The `\xNN` fallback is replaced by `\uNNNN`, or `\u{NNNNN}` above the BMP,
uppercase hex in both, gated by `rubyPrintable` in
`go/internal/query/inspect_printable.go` — a 739-range `unicode.RangeTable`
generated from the exhaustive Ruby capture by
`review-2026-08-02-coercion/generate-printable-table.rb`.

The table is captured rather than expressed with Go's `unicode` package for two
independent reasons, both measured:

- Ruby's predicate is Onigmo's, not a general-category test. U+00AD, U+200B and
  U+FEFF print raw while U+0085, U+2028 and every unassigned codepoint escape.
  The closest category expression, `IsGraphic || Cf`, is structurally right and
  still wrong on 148,083 codepoints.
- Those 148,083 are Unicode version skew: Ruby 4.0.6 is on 17.0.0 and Go
  1.26.5's tables are on 15.0.0. This is the same two-runtime coupling
  `newerUnicodeLower` works around for `downcase`, at a scale where an override
  table is not the answer.

Surrogates cannot exist in a Ruby UTF-8 String, so they are absent from the
capture and land as non-printable.
