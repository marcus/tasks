## What changed

**Finding 1 — `$-X`.** `globalName` grows a `-` branch, `dashGlobalName`: bare
iff exactly one character follows the dash, and that character is an ASCII
letter, digit, or `_`, or a non-ASCII rune passing `symbolPrintable`. The
review's instruction to reuse `symbolPrintable` rather than copy the predicate
is followed literally, so `$-é` is bare and `$-͸` quotes for exactly the reason
`:é` and `:͸` do. `$-\x01` and `$-\x7F` need no special case — they fail the
ASCII identifier-character test, as the review said they would. Length is
strict in both directions: `$-` alone and `$-ab` quote.

**Finding 2 — the leading-zero digit global.** Taken in the review's second,
preferred form: `0` moves into `specialGlobals` — the twenty-one-character set
Ruby's own `SPECIAL_PUNCT` bitmap actually holds — and the digit branch narrows
to `name[0] >= '1' && name[0] <= '9'`. `$0` is therefore bare through the
punct branch, exactly where Ruby puts it, and `$00`, `$01`, `$0123` quote.

The review warned that narrowing the digit branch without moving `0` across
turns a non-defect into a defect; that is not a hypothetical.
`TestGlobalNameUsesTheFixedSpecialSet` caught precisely that ordering mistake in
the first draft of this repair, where the narrowed digit branch returned early
for `$0` before the punct branch could see it. The branch now falls through.

the two new sweeps; it did not re-judge the review's findings and did not read
past `globalName`. Three things are still owed on this slice, unchanged by this
